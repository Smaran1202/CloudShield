# S3 bucket default encryption does not use a KMS key

What the rule checks: the bucket's default encryption setting. This finding means it is not set to
use a key in the AWS key management service (KMS).

Why it matters: S3 already encrypts every new bucket by default with keys that S3 manages, so a
bucket with no encryption at all is almost never real. Using your own KMS key adds control: you can
decide who may use the key and you get an audit trail of key use. This is an informational finding
and does not raise the risk score.

What the fix does: it sets the bucket's default encryption to use a KMS key that the user chooses.
The patch contains a clearly marked placeholder for the key ARN, which the user must fill in.

What can break: every role and user that writes or reads objects in the bucket needs permission to
use the key. Without it, uploads and downloads fail. Objects that already exist keep the encryption
they were written with.

How to talk about it: say that this is a hardening step, not an urgent exposure.
