# S3 bucket does not block all public access

What the rule checks: an S3 bucket has a public access block with four switches. This finding means
the block is missing, or at least one switch is off.

Why it matters: without all four switches on, an access control list or a bucket policy can make the
bucket's objects readable by anyone on the internet. The block is a safety net that holds even if
someone writes a permissive policy by mistake.

What the fix does: it turns all four switches on for the bucket. It changes only the public access
block. It does not change the objects, the policy text or the other settings.

What can break: anything that depends on anonymous access to the bucket, for example a public
website or files served directly from the bucket. A bucket policy that allows a public principal
stops working for public requests once the matching switch is on. Website hosting and ACLs are not
collected, so their effect can only be called unknown.

How to talk about it: be direct about the exposure risk, but do not say the bucket is publicly
reachable unless the evidence shows a public policy. The evidence shows configuration, not traffic.
