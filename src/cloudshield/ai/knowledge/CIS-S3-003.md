# S3 bucket versioning is not enabled

What the rule checks: whether versioning is turned on for the bucket. This finding means it is off
or suspended.

Why it matters: without versioning, an overwritten or deleted object is gone. A mistake, a bad
deployment or a malicious delete cannot be undone from the bucket itself. With versioning, earlier
versions can be restored.

What the fix does: it turns versioning on for the bucket. Existing objects are not changed. From
then on, every overwrite or delete keeps the earlier version.

What can break: very little in terms of access, because versioning does not change who can read the
bucket. The main effect is cost: old versions use storage until a lifecycle rule removes them.
Versioning can be suspended later but not fully switched off.

How to talk about it: this is a resilience and recovery measure, so describe it as protection
against data loss.
